# Laporan Audit: SEC-001 (Hardening IDOR, CORS/backup exposure, aksesibilitas, performa Android)

**Tanggal Audit:** 2026-09-25
**Auditor:** Agent 3 (peran, dijalankan sesuai `blueprint/CONTROL-PLANE.md`)
**Item:** SEC-001 — hardening IDOR, CORS, backup exposure, aksesibilitas, performa Android
**Metode verifikasi:** Statis (inspeksi source lintas `src/app/api`, `src/services`, `next.config.ts`,
`src/styles`, `public/`; tanpa proses runtime)
**Status Akhir:** `PASS` — 0 temuan critical/high; 3 catatan risiko rendah (tidak menghalangi)

## Ringkasan temuan

Audit menelusuri lima area. Tidak ditemukan kerentanan critical/high. Implementasi sudah
memenuhi blueprint `security/SAFETY-DAN-AKSES.md` secara statis: tidak ada UI yang menjadi
satu-satunya pengaman, kepemilikan data ditegakkan di layer service, dan setiap mutasi
state-ubah memerlukan autentikasi + CSRF.

## Bukti per area

### 1. IDOR — kepemilikan dari session, bukan parameter URL

- `api/v1/profile/route.ts`, `api/v1/account/*` — identitas diambil dari `auth.principal`
  (session), bukan body/params; tidak ada ambil data pengguna lain by ID.
- `api/v1/certificates/[number]/route.ts` → `ExamService.verifyCertificate` menolak bila
  `principal.role !== 'OWNER' && certificate.principal_id !== principal.id` (NOT_FOUND,
  tidak membocorkan keberadaan).
- `api/v1/groups/[id]` → `getGroupDetail` hanya mengembalikan grup `status='APPROVEDED'` +
  metadata minimal; isi grup tidak bocor ke non-anggota; `membership_status` hanya untuk viewer.
- `api/v1/articles/[id]` → `policy.decide({ principal, articleId })` mengecek `access_level`
  (PUBLIC) atau MEMBER APPROVED+entitlement; `isOwner` terpisah.
- `api/v1/profiles/[username]` dan `api/v1/software/[slug]` meneruskan `viewerId`/`principal`
  ke service sehingga visibilitas diputus server-side.

### 2. CORS / header keamanan

- `next.config.ts` `securityHeaders()`: `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`,
  `Permissions-Policy` (camera/mic/geo/payment/usb off), CSP ketat `default-src 'self'`,
  `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`, `form-action 'self'`.
- `connect-src` terpisah per profile: `'self'` (production) vs `'self' localhost:* (dev).
  HSTS hanya production karena HTTPS wajib — tidak melemahkan dev localhost.
- Tidak ada origin eksternal yang diizinkan runtime; tidak ada font/CDN eksternal.

### 3. Backup / data exposure

- `public/` hanya 3 aset SVG/JPG (emblem, wordmark, `shop/multimeter-digital.svg`); tidak ada
  file `.env`, `.sql`, `.key`, atau dokumen di folder statis.
- `backup-local/`, `cloud-local/`, `database/` tidak dilayani sebagai static/route; pemeriksaan
  endpoint API tidak menemukan rute yang membaca direktori tersebut.
- `api/v1/operasi/backup`, `security/inspect`, `security/threats` memerlukan
  `authenticateRequest(request,'OWNER')` **dan** `assertRequestCsrf(...,'OWNER')`.

### 4. CSRF & rate limit

- Seluruh mutasi state-ubah `api/v1/owner/*`, `api/v1/account/*`, `api/v1/security/*`,
  `api/v1/operasi/*` memanggil `assertRequestCsrf` (cookie + header `x-csrf-token`).
- `api/tools-gate.ts` `guardToolExecution` = `authenticateRequest('MEMBER')` +
  `assertRequestCsrf('MEMBER')` + reserve trial idempoten; dipakai `pdf/process` dan
  `utilities/rumus` (POST output-generating).
- Rute tanpa CSRF adalah yang memang tidak boleh memerlukannya (login, register, refresh,
  challenge, verify-contact) atau sudah dilindungi jalur lain:
  - `ebelanja/products/[id]/buy` kini hanya mengembalikan `DEPENDENCY_UNAVAILABLE`
    (checkout rituan sudah dipensiunkan).
  - `ebelanja/products/[id]/track-click` tracking view-only.
  - `public-feedback` → `PublicFeedbackService.enqueue`: moderasi lokal `LocalModerationEngine`
    + `consumeRateLimit` (20/jam per sender) + tulis ke `owner_inbox_items` (hanya Owner baca).
  - `recovery` → guard `RATE_LIMITED` sebelum `requestRecovery`.
- Login/register/owner-login memakai rate-limit terpisah (tercatat pada file route-nya).

### 5. Aksesibilitas & performa Android

- `prefers-reduced-motion` hadir di 5 sheet CSS (`globals`, `redesign`, `madevi-on`,
  `interface-refresh`, `header-fx`); D08/D09 menjamin motion hanya atmosfer dan konten state
  final sejak first paint.
- Target sentuh minimum 44px diterapkan di `globals.css`, `interface-refresh.css`,
  `redesign.css` (audit ADMIN-001 juga memperbaiki target <44px pada Shop).
- 63 komponen memakai atribut `aria-*`; `role="alert"`/`aria-live` pada state error
  (owner-console, exam, owner-exam-panel).
- Tidak ada `eval`/`new Function`; `dangerouslySetInnerHTML` hanya 2 lokasi, keduanya aman:
  `THEME_SCRIPT` (konstanta statis tema) dan `career-panel` `buildDocument` yang escape HTML
  (`&`, `<`, `>`, `"`).
- Server-side processing PDF/rumus dibatasi gate trial + idempotency (biaya Android terjaga).

## Catatan risiko rendah (tidak menghalangi PASS, tidak butuh revisi source)

1. `question-bank-editor.tsx` validasi sisi klien `20`/`5` — konsisten dengan policy saat ini,
   tapi akan ketinggalan bila policy versi baru mengubah jumlah (sudah dicatat di audit
   ASSESS-001 untuk backlog Agent 1). Server tetap penegak utama.
2. `ebelanja/products/[id]/track-click` tidak CSRF — view-only, dampak rendah; layak backlog
   bila Owner ingin konsistensi penuh.
3. Verifikasi runtime (rate-limit benar-benar membatasi, CSP tidak memutus fungsi lokal)
   tertunda sampai izin proses diberikan; semua bukti saat ini statis.
